Overview

SmartEduTrack records class attendance from students' phones. A student is only marked present after scanning the code shown in class while their phone is inside the lecture venue. Lecturers and administrators see the results in attendance reports.

The problem

Paper attendance is slow in large classes, and it is easy for one student to sign in for a friend who is not there. A plain QR code has the same weakness, because a photo of it can be sent to someone outside the room. The system needed to check two things at once: that the student has the current code, and that they are physically in class.

What I built

I built the whole system on my own: the React interface for all three user roles, the Node.js and Express API, the MongoDB data model, login and access control, offline support, testing and deployment.

How attendance is recorded

  1. The lecturer starts a session for a course. The app shows a QR code that refreshes every few seconds, along with a session ID.

  2. The student opens Scan Attendance on their phone, enters the session ID and scans the code.

  3. The phone's GPS position is checked against the geofence around the lecture venue, so a scan from outside the room is not accepted.

  4. The attendance is saved and appears in the student's record, the lecturer's course report and the administrator's dashboard.

If the student's phone has no internet connection, the attendance is stored on the device and sent automatically once it is back online.

Three roles, three views

Student
  • Scans attendance with the session ID and QR code.
  • Registers for courses.
  • Sees their own attendance per course, with a percentage and status.
Lecturer
  • Starts and ends attendance sessions for a course.
  • Shows a QR code that refreshes automatically.
  • Loads a course report with each student's matric number, sessions attended and percentage.
Administrator
  • Sees attendance across the whole faculty, filtered by department and level.
  • Gets a count of student-course records below 75%, flagged as at risk.
  • Manages the list of courses.
All roles
  • One login page for every role. JWT tokens decide which views each user can open.
  • New students can register themselves.

Technology

React
The interface for students, lecturers and administrators.
Node.js + Express
The REST API behind sessions, scans, courses and reports.
MongoDB
Stores users, courses, sessions and attendance records.
JWT
Login and role-based access for the three user types.
IndexedDB + Dexie.js
Holds scans on the phone while it is offline, then syncs them.
Render
Hosts the live demo.

Testing and deployment

I tested the backend end to end with Postman. The system is deployed on Render, where the live demo runs, and the full source code is public on GitHub.
